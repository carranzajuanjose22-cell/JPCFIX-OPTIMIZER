# Arquitectura

Core define modelos, contratos y protocolo cerrado `RunnerRequest`. Application contiene `PowerOptimization`: reglas deterministas, preview, respaldo, aplicación, verificación y compensación. Infrastructure integra PowrProf, Kernel32, WMI, JSON atómico y puntos de restauración. Desktop contiene vistas XAML, ViewModel y cliente UAC. Runner es un ejecutable independiente con manifiesto requireAdministrator y confirmación propia. Desktop usa asInvoker. Las dependencias se inyectan por constructor en la raíz de composición; no se necesita contenedor DI externo.

Flujo: leer → comprobar disponibilidad del original y destino → simular → confirmar → UAC → validar protocolo → adquirir mutex global → proteger almacenamiento → auditar intención → releer y confirmar → persistir Prepared con flush → comprobar estado otra vez → aplicar API → verificar → persistir Applied. Un error intenta compensar sin sobrescribir un tercer plan. Si no puede verificarse la compensación se guarda RecoveryRequired. La cancelación no interrumpe una transacción después del respaldo.

La UI nunca escribe respaldos ni ejecuta cambios de energía directamente. Lee el historial persistente al inicio y avisa si encuentra Prepared/RecoveryRequired; recuperar es una acción explícita. El ejecutor bloquea nuevas aplicaciones con operaciones pendientes. La reversión se identifica por GUID de operación; no recibe rutas de archivos. Cada operación conserva fecha, identidad, original y destino al actualizar el estado; Audit conserva eventos separados.

Los JSON se escriben en un temporal único, se vacían a disco y se sustituyen con File.Replace o File.Move en el mismo directorio. No hay garantías frente a fallas físicas de almacenamiento; ante registros inválidos se informa error y no se inventa un estado. El bloqueo global serializa instancias de JPCFIX; otras herramientas pueden cambiar Windows fuera de ese bloqueo. Se revisa el estado antes y después, sin pretender una transacción distribuida con Windows.

Diagnóstico ejecutado en Task.Run, consultas WMI con tiempo límite y errores por proveedor. CPU: muestra de LoadPercentage del proveedor; RAM/espacio/procesos: instantáneas. MediaType solo se informa desde MSFT_PhysicalDisk, sin adivinar por nombre ni atribuirlo a una letra. No se ejecuta PowerShell. Punto de restauración: proveedor WMI SystemRestore.CreateRestorePoint y comprobación de nueva secuencia; un fallo no afecta respaldos de energía.

Referencias oficiales: [administración de planes](https://learn.microsoft.com/windows/win32/power/managing-power-schemes), [PowerEnumerate](https://learn.microsoft.com/windows/win32/api/powrprof/nf-powrprof-powerenumerate), [CreateRestorePoint](https://learn.microsoft.com/windows/win32/sr/createrestorepoint-systemrestore).
